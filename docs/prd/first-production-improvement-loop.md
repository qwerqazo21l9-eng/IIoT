# PRD：首个产线诊断与改善闭环

状态：已发布；[父 PRD Issue](https://github.com/qwerqazo21l9-eng/IIoT/issues/1)。
日期：2026-10-06。
已确认：首个交付切片、spec-driven、五个测试边界、页面清单及映射、完整 UI 设计描述与状态策略。

## 问题陈述

工程师面对产出不足时，需要分辨工位自身异常暂停与缺料、阻塞、换型、观测缺失，并查明候选瓶颈源与受影响工位。单独的告警或局部节拍变化不足以证明产线产能受到影响。

管理者需要基于可追溯证据审批改善提议，并通过受控实验判断良品 JPH 是否改善。当前项目只有领域和架构文档，没有可运行的业务闭环，不能提供上述证据。

## 解决方案

交付一条四工位模拟产线的本地可运行闭环：OPC UA / EdgeX 接入原始事件，经 Kafka 和 Java Flink 重建状态、计算指标与规则证据，由 PostgreSQL 保存业务记录及版本化结果，Spring Boot 提供诊断、审批和实验协调，React + TypeScript 工作台供工程师与管理者使用。

工程师查看产线表现与候选诊断，核对证据并提交改善提议；管理者批准或驳回；工程师对已批准提议运行基线与改善配置的配对实验，查看良品 JPH、质量、期末在制品及有效性限制。改善执行仅作用于模拟器。

首期至少完成一组配对实验并贯通一次审批闭环。重复次数可配置，结果展示实际完成组数及波动；单组结果不得宣称统计显著性或最终产能收益。本切片是整体计划的第一阶段，后续目标仍由整体框架管理。

### 状态策略

- **加载：**首次加载使用局部骨架；刷新保留现有数据，显示更新时间和刷新状态。
- **空：**区分尚无数据、筛选无结果和暂无诊断，并提供对应操作。
- **错误：**失败区块提供重试，其他可用区块继续显示；旧数据明确标为未更新。
- **禁用与提交：**说明禁用原因；提交中防止重复操作，失败保留输入。
- **业务不确定性：**观测缺失、无法判定、无法评价与系统错误分别表达；未知数据不记为零。
- **上传：**本期没有上传流程。

## 实现决策

### 首期模块边界

遵循 ADR-0001 至 ADR-0006 的职责划分。模拟器、EdgeX 接入、Kafka、Java Flink、PostgreSQL、Spring Boot 和 React + TypeScript 构成首期运行链路。Spring Boot 内分配置、诊断、提议审批、实验与报告模块，业务状态通过明确接口改变。首期采用规则诊断；算法服务和模型生命周期在后续切片实现。

### 模拟产线与真值隔离

提供一条四工位、有限缓冲的产线，工件具有稳定身份，具有产品和生产批次配置、显式换型及少量不良品。主演示在第二工位注入额外暂停；验收覆盖正常运行与其他工位暂停。模拟器输出可观测的动作开始、结束、缓冲与质量等事实；隐藏故障位置、故障标签与未来事件仅提供给独立验收工具。正常参数变化和换型不能直接作为故障答案。

### 统一事件契约

OPC UA 经 EdgeX 映射到统一事件，保留稳定事件身份、运行标识、产线、工位、设备、工件及产品身份、事件类型、设备序号、原始时间、接收时间、质量、映射配置版本和格式版本。相关字段不适用时明确缺省语义。单位在配置中明确。微停属于推断结果，不作为设备直接输出的故障标签。缺号、重复、无效时间与未知身份有可观察处理结果；事件格式允许后续协议和模型版本扩展。

### 工位状态与规则诊断

Flink 以事件时间重建加工、暂停、缺料、阻塞、换型和观测缺失。各产品与动作使用版本化正常时长和规则阈值，动作未完成时可形成疑似判断，结束后复核；不能使用未来事件提前生成在线结论。乱序容忍与超时参数可配置并进入运行记录。超出首期处理窗口的事件明确标记，不静默覆盖旧结果。跨工位证据不足或时间质量不足时输出无法判定，候选源与受影响工位分别保存。

### 指标与结果版本

良品 JPH = 统计区间内产线出口良品数 / 统计区间小时数；预热不计入统计区间，区间采用起点包含、终点不包含的约定。良品只在产线出口计数，工位完成数不能替代产线良品数。同时保存不良品数、期末在制品、数据完整性、时间可信度、统计范围及输入、配置、规则、计算版本。整体含换型结果与稳定生产区间分别标明，不混用口径。未知数据不填零，零时长无有效 JPH，基线 JPH 为零时相对收益显示不可计算。指标、状态与诊断支持追溯至证据事件；首期只保存演示与验收所需证据，不将 PostgreSQL 扩展为长期全量原始事件存储。

### 重复投递与业务幂等

原始事件使用稳定身份去重，计算结果与诊断使用业务标识及版本避免重复写入。提交提议、审批、启动实验支持请求幂等及状态冲突检查。重发不能产生重复良品计数或多次改善执行。首期验证约定重复投递场景，不据此宣称完整故障范围内端到端恰好一次。

### 改善提议与审批状态机

提议保存诊断证据版本、目标工位、白名单改善动作、参数、预期影响、验证条件与提交人。工程师提交后进入待审批，管理者可批准或附必填理由驳回；已处理提议只读。批准绑定具体提议和证据版本，修改动作、参数或依据须重新提交审批。并发操作通过版本检查阻止覆盖；保存操作者、时间、前后状态与意见。允许动作首期至少包含减少指定工位模拟额外暂停诱因，不能任意调用设备指令。

### 演示角色与后端授权

本地提供不同身份的工程师和管理者演示主体，角色切换不是正式认证。Spring Boot 对提交、审批和启动权限独立校验：工程师提交与启动，管理者审批；同一主体不得审批自己的提议。读取对两种角色开放。非法请求不得改变业务状态；未知身份拒绝操作。本地演示身份机制不得作为面向外网的生产认证方案。

### 配对实验协调

实验启动时再次检查批准状态、提议版本和参数；后端生成并关联两个独立运行。配对两组保持订单、产品组合、初始工位与缓冲状态、预热、统计时长及正常随机过程相同，仅改变获批改善因素。质量随机结果按工件身份保持一致；正常与故障随机过程独立，避免改善改变随机数消费顺序。重复组使用记录在案的不同配对种子。实验状态为待运行、运行中、完成、失败；仅两组均完成且有效性校验通过的配对参与汇总。失败重试创建可追溯运行尝试，旧记录保留，不合并重复计数。

### 实验报告有效性

报告展示两组良品 JPH、绝对及相对变化、良品与不良品数、期末在制品、实际完成配对数、各配对差值和波动。校验统计范围一致、配置差异仅为批准动作、输入完整性和时间质量足够、两组均完成；失败时标为无法评价并列原因。单组标明证据不足以评价波动，短期在制品释放可能影响收益解释。保留实验、运行、输入、提议、审批、配置、规则、计算与报告版本；本期模型版本标为未使用。

### 工作台服务接口

服务提供产线与批次查询、时间范围指标、工位状态、可分页诊断列表、诊断证据详情、提议提交与查询、审批、实验创建与启动、运行状态和结果查询。查询携带时间范围与结果版本；写操作携带请求身份、幂等标识和适用的预期版本。契约区分参数错误、无权限、对象不存在、状态冲突与服务错误，不能将业务无法判定编码为系统错误。列表筛选和详情返回状态可恢复；实验进度通过定时查询获得，不要求新增实时推送组件。

### 本地演示交付

提供统一启动说明、服务就绪检查、版本化演示配置、确定性种子和验收入口。交付正常生产、暂停诊断、提议驳回与批准、配对改善、观测缺失、重复投递的可复现步骤及实际结果。服务未就绪时演示入口明确失败，不生成伪造报告。记录所需环境和资源；具体版本与启动参数在实现交付时确定。

## 测试决策

当前没有实现代码和已有测试先例。测试以外部输入、持久化结果、服务响应与用户行为为依据，不断言内部类结构。五个测试边界已由用户确认；优先通过业务 API 贯通，协议和流计算边界保留必要独立契约测试。

### 模拟产线事件输入测试边界

相同配置和种子产生可复现工件流；验证四工位顺序、有限缓冲、质量与换型事实。正常、任意工位额外暂停和观测缺失输入可独立生成。检查诊断输入不包含隐藏真值与未来数据；实验两组对应工件质量及正常随机条件一致。

### EdgeX 与接入统一事件测试边界

至少一项集成验收经过实际 OPC UA 服务及 EdgeX，不能仅以假统一事件代替协议链路。断言身份映射、序号、原始时间、单位、质量和配置版本正确。重复、缺号、未知设备和无效字段均得到明确处理结果；原始事实不被改写为隐藏故障标签。

### Kafka 与 Flink 计算输出测试边界

通过 Kafka 投递已知事件序列，检查持久化状态、诊断证据和指标。覆盖正常加工、缺料、阻塞、换型、额外暂停、观测缺失、容忍窗口内乱序和重复投递。检查良品仅计一次、预热排除及区间边界正确，源工位与受影响工位不混淆；证据不足时拒绝判断。暂停覆盖 0.5–10 秒代表性场景，记录检出、延迟、漏检与无法判定，不预设所有暂停均检出。最终每线每 8 小时误报目标留待独立评估，本切片不得声称已达成。

### Spring Boot API 与业务审批测试边界

经实际 HTTP 和数据库验证提议提交、批准、驳回、审计、状态冲突与幂等。未批准、参数版本不一致、无权限或自审批请求均不得启动改善。并发审批只有一个有效决定，重复启动不创建重复执行。React 浏览器验收映射 US-1 至 US-11，核对后端真实状态、刷新与失败保留输入，并在桌面和窄屏检查导航、表格与文字无重叠；禁用按钮不是后端权限测试的替代。

### 改善实验结果报告测试边界

通过业务 API 完成至少一组“诊断 → 提议 → 独立管理者批准 → 配对实验 → 报告”。核对批准因素是两组唯一干预差异，JPH 与出口良品独立核算一致，报告展示实际改善、无改善或无法评价的结果，不要求每次均获得正收益。验证基线零值、单组、重复组、运行失败、数据缺口及配置不一致时的报告语义；同种子与版本可再次运行核验。保存自动验收结果和运行记录。
