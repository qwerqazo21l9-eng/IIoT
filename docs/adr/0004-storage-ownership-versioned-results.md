# 分离时序查询、业务记录与长期原始归档

已确认，尚未实现。IoTDB 承担时序采样查询，PostgreSQL 承担业务记录和版本化指标结果，对象存储保存长期原始事件、数据集、模型与报告；Kafka 承担实时消费与近期重放。

相比单库或仅靠 Kafka 长期保留，此分工使业务审批与时序查询各有明确存储职责，也允许事件过期后复核实验。暂不引入 Neo4j，基础产线拓扑不需要完整资产图数据库。

跨库写入不假设同时成功，需重试、核对和修复。归档记录范围、数量、校验值与格式版本；报告绑定数据、配置、模型和计算版本。历史重放产生新结果版本，保留修正依据与旧结果；派生数据的可重建性不代替审批、审计等业务记录的持久化与恢复设计。
