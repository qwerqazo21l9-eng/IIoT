# 使用 Kafka 与 Flink 构建可重放的工业计算链路

已确认，尚未实现。Kafka 保存可重放事件，Flink 负责工位状态、事件时间、跨工位关联和指标计算；补传触发独立历史重放任务，核验后发布修正版，实时链路继续运行。

相比自建计算服务或在实时任务中保留所有长时间窗口，此方案复用状态恢复能力，并隔离历史修正与实时负载。代价是维护消息与计算基础设施，以及恢复起点状态、影响时段和结果发布版本。

端到端结果一致性需覆盖事件去重、计算状态、持久化输出和重复发布，不能仅因启用检查点就宣称恰好一次。中心仅在达到约定持久化条件后确认，边缘据此清理缓存；工作节点故障允许短暂暂停，但已确认事件须在约定故障范围内保留并可核验。
